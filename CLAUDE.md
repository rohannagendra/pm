## ProjectFlow

## Project Overview

ProjectFlow is a project management app built with Next.js 16 (App Router), React 19, TailwindCSS v4, shadcn/ui, and Zustand. Data is persisted in a SQLite database via Prisma ORM, accessed through Next.js API routes.

## Commands

- `npm run dev` - Start development server (Turbopack)
- `npm run build` - Production build (also runs TypeScript checking)
- `npm run start` - Serve production build
- `npm run lint` - Run ESLint
- `npx prisma generate` - Generate Prisma client after schema changes
- `npx prisma migrate dev` - Run database migrations
- `npx prisma studio` - Open database GUI browser
- `docker-compose up` - Run app in Docker container
- `docker-compose down` - Stop Docker container

## Architecture

### Database
- **Prisma** ORM with **SQLite** (configurable via `DATABASE_URL` env var)
- Schema at `prisma/schema.prisma` defines three models: `Task`, `Project`, `CalendarEvent`
- Prisma client singleton at `lib/prisma.ts` (cached on `globalThis` in dev)
- Database file at `prisma/dev.db` by default
- Migrations in `prisma/migrations/`

### API Routes
- RESTful routes under `app/api/` for all CRUD operations
- `GET/POST /api/tasks`, `PUT/DELETE /api/tasks/[id]`
- `GET/POST /api/projects`, `PUT/DELETE /api/projects/[id]`
- `GET/POST /api/events`, `PUT/DELETE /api/events/[id]`
- `POST /api/seed` - Seeds database with sample data

### State Management
- Zustand store at `lib/store.ts` manages client-side state
- Three entity types: `Task`, `Project`, `CalendarEvent`
- Store fetches and mutates data through API routes
- All components access state via `useAppStore()` hook

### Routing
- Next.js App Router with 5 page routes: `/`, `/tasks`, `/projects`, `/calendar`, `/settings`
- Each route page is a thin wrapper that imports a component from `components/`
- Layout in `app/layout.tsx` renders the `Sidebar` component alongside page content

### Styling
- TailwindCSS v4 with `@tailwindcss/postcss` plugin
- Dark mode via `class` strategy on `<html>` element
- shadcn/ui components in `components/ui/` (16+ components from Radix UI)
- Theme variables defined in `app/globals.css` using CSS custom properties

### Docker
- `docker-compose.yml` runs the app on port 3000
- SQLite data persisted in a named Docker volume (`sqlite-data`)

### Key Patterns
- All page components are client components (`"use client"`) since they use Zustand
- Task status enum: `"todo" | "in-progress" | "review" | "done"`
- Task priority enum: `"low" | "medium" | "high" | "urgent"`
- IDs generated by Prisma using `cuid()`
- Dates stored as ISO strings, due dates as `YYYY-MM-DD` strings
- Drag-and-drop on Kanban uses native HTML5 drag events (no library)

## Dependencies of Note

- `prisma` / `@prisma/client` - ORM for database access
- `@prisma/adapter-better-sqlite3` - SQLite adapter for Prisma
- `zustand` - Client-side state management
- `date-fns` - All date formatting and manipulation
- `lucide-react` - All icons
- `@radix-ui/*` - Underlying primitives for shadcn/ui components
- `tailwindcss-animate` - Animation utilities for component transitions
